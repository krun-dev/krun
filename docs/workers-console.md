# Workers 控制台

Workers 页面属于主 React/Vite 静态控制台，入口是 `/?page=workers`。开发启动与
同源代理配置见 [本地开发](local-dev.md)；生产静态托管见 [部署](deployment.md)。

Workers 和对象存储列表支持按名称或 ID 进行不区分大小写的包含搜索，搜索范围覆盖整个
组织。每页可选 20、50 或 100 条，提供上一页和下一页；修改搜索条件或每页条数时返回
第一页。列表与详情展示创建时间，详情通过查询参数中的稳定 ID 单独加载，刷新不依赖
该资源是否在当前列表页。

Workers 列表接口 `GET /api/v1/orgs/{org}/workers` 接受 `q`、`limit`（1–200，
默认 100）和 `after`，返回 `items` 与可选的 `next_after`。游标按资源 ID 推进，搜索先于
分页；`worker_id` 用于独立读取一个可访问的Worker 摘要，不受搜索和游标影响。CF 兼容
接口保持原有协议与响应结构，不使用控制台分页参数。

## 页面流程

1. 从组织 Workers 列表进入 Worker，选择目标环境后上传本地目录或 ZIP，也可以从配置好的 GitHub / GitLab 仓库构建。上传会自动识别静态产物和 Wrangler 项目。[部署本地项目](../user-docs/src/content/docs/guides/deploy-local-project.md)
2. 查看持久化 Build 状态、编译日志和对象存储 Artifact。
3. 选择成功构建并发布到目标环境；Operation 经认领、验证、提交和 runtime ack
   最终收敛到 available。
4. 用 CAS revision 修改环境变量、Worker 域名或执行回滚，避免覆盖并发更新；预览环境
   的创建和删除也通过Worker 行 CAS 仲裁，多个控制面副本不会并发突破数量上限。
5. 「配置版本 → 管理环境草稿」中的环境变量按“变量名 / 值”逐行编辑，默认文本；对象、数组、数字等可选择 JSON 类型。
   “高级设置：在代码中读取版本信息”可填写版本信息变量名，例如 `VERSION_INFO`，
   代码通过 `env.VERSION_INFO.id` 读取当前版本 ID；留空关闭。环境变量与对象存储绑定独立
   保存，保存一个区域不会提交或清空另一区域的草稿，下次发布时生效。
6. 环境草稿中的 Secrets 每行一个，支持新增、替换和确认删除。替换时输入新值，旧值不回填；
   眼睛按钮只显示本次输入。值以 AES-256-GCM 加密入库，控制台和公开 API 不回显
   已保存原值。已有部署时修改会复用当前 Artifact 自动发布新 Version；首次部署前
   只保存配置，不重新构建代码。
7. 「环境管理 → 创建预览环境 → 新建预览默认配置」提供新建 Preview 的默认环境变量、Secrets 和对象
   存储绑定，三个区域独立保存。创建时复制一次；修改只影响之后新建的 Preview，已有
   Preview 和生产环境不受影响。
8. 从历史中查看 Version，在“调用测试”中经配置好的 kgateway 验证业务响应。

## 命名配置版本

选择环境后进入「配置版本」，可以从环境草稿、当前生效版本或已保存配置创建一份新配置，
填写“XXX 测试”等名称与说明。变量、R2 绑定、版本信息绑定、静态资源绑定与 Secret
版本引用一起冻结；修改通过“复制并修改”创建新记录，不覆盖历史。可以先保存配置再构建代码。

新配置编辑器内的 Secret 新增、替换和删除先暂存在本次编辑中，保存新配置时加密入库，
不会触发部署。取消编辑会丢弃这次草稿；已经保存的值不回显。环境草稿和 Cloudflare
Secrets API 的原有行为保持不变：已有部署时直接修改 Secret 仍会自动发布。

“发布并生效”复用当前代码制品生成新的标准 Version，并使用普通 Deployment 队列验证和
发布。恢复历史配置也复用当前代码，不会顺带回滚代码。首次部署时在确认框中选择成功的
Build。确认框冻结目标配置、代码版本、环境配置 revision 和部署 revision，期间发生并发
修改会拒绝提交并要求重新核对。“当前生效”只跟随 `confirmed_version_id`，排队、验证或
committed 阶段仍展示上一个已确认版本；失败不会把候选配置标为生效。

配置按环境隔离；选择项保存在查询参数 `configuration` 中。非活动历史保留 30 天，当前、
已确认和进行中的部署引用的配置继续保留，后台每批最多清理 1000 份及其绑定。删除预览时
同时删除该预览的配置版本，重新创建同名预览不会继承旧历史。

## 代码与配置发布版本

通常在成功构建旁点击“发布”即可，无需先创建版本。需要提前固定发布内容时，选择目标
环境，在“构建”中打开该构建的“更多构建操作”，选择“创建待部署版本”。确认框
展示来源构建、目标环境和将冻结的环境配置，可填写版本标签和说明；配置在提交前变化
时拒绝创建，需重新核对。创建不会改变线上部署，也不会生成访问地址。

创建成功后自动进入同一环境的“版本与流量”，定位并突出显示新版本。列表按创建时间
倒序展示版本、关联构建、配置 revision 和部署状态，展开“查看冻结配置”可核对普通
变量、存储和元数据绑定。Secret 只展示冻结引用的提示，不返回值。页面用查询参数保留
环境和页签，刷新后仍可查看。选择“部署此版本”并确认后，使用该版本冻结的代码与
配置启动发布，后续环境配置变更不会合入；发布进度在同页展示。固定地址在部署验证
通过并提交后生成。

版本与部署记录分别分页，每页可选 20、50 或 100 条，翻页互不影响。版本可按 ID、标签、
说明或保存者搜索，部署记录可按部署 ID、版本 ID 或状态搜索。两个列表接口分别是
`GET /api/v1/orgs/{org}/workers/{worker}/versions` 和 `/deployments`，接受
`environment`、`q`、`limit`（1–200，默认 100）和不透明的 `after` 游标，返回
`items` 和 `next_after`。先做环境过滤与权限检查，再按创建时间倒序、同时间 ID 升序分页。
CF 兼容接口继续使用 Cloudflare envelope 与既有完整列表，不应用控制台的搜索和游标参数。

点击列表、当前部署摘要或部署记录里的版本号，读取 `/versions/{version}` 并打开详情，
不依赖该版本是否在列表当前页。详情展示完整版本 ID、保存者 ID 与保存时的姓名、创建
时间、标签、说明、制品、关联构建和冻结配置。通过构建发布、保存待部署版本或修改
Secret 创建的新版本都会保存创建者；复用已有版本不会改写原创建者。

顶部摘要区分 runtime 已确认的当前生效版本和已提交、正在生效的目标版本。部署提交时
按钮展示忙碌状态并阻止重复点击；受理后自动定位到发布进度，持续展示排队、验证、
提交后等待 runtime 确认、成功、失败或被替换。只有操作进入 `available` 才展示部署
成功；失败显示错误详情。部署记录展示创建与提交时间，可回看仍保留的操作进度。

构建与发布队列支持控制面重启和多副本抢占：认领使用条件更新及租约，副作用必须
幂等。Version 提交不保证边缘立即生效，runtime 通过 config revision、snapshot 和
ack 最终收敛。

调用接口只接受相对 URI，目标 Gateway 与 Host 来自平台配置。平台凭据不会转发给
业务；不跟随重定向，响应正文有大小限制并以转义文本显示。

## 网络配置

组织侧选择平台允许的 Network Profile 和域名，不提供资源池选择或迁移入口。
基础设施目录来自主 YAML，匹配关系见 [Workers 资源池](workers-pools.md)。

仓库内的 [`examples/workers-fullstack`](../examples/workers-fullstack/README.md) 是完整
验证夹具：同一个 Version 同时包含 Worker API 和纯静态前端，并由 kind E2E 实际构建、
发布和调用，不是只靠 mock 或单元测试证明。

自动化测试与浏览器验收入口见 [验证说明](verification.md)。

「对象存储」中点击桶名称可以浏览目录、上传下载、查看元数据和删除文件。对象权限
独立于桶管理权限，文件内容直接传输到对象存储；配置、API 和验收入口见
[文件与分发](bucket-objects.md)。
